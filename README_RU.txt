ClipHouse 3.0 — общий буфер обмена с SQLite
===========================================

ЧТО НОВОГО
----------
- История записывается сразу в SQLite (history.sqlite3), а не в JSON.
- Главная страница запрашивает последний текст и быстрый счётчик записей; счётчик обновляется триггерами SQLite, без полного пересчёта истории на каждом опросе.
- История загружается постранично: максимум 50 записей на страницу.
- Есть поиск по словам/фразам. Если встроенный SQLite поддерживает FTS5,
  используется полнотекстовый индекс; иначе включается резервный поиск LIKE.
- Компьютеры синхронизируют записи и удаления фоновыми партиями, а не отправляют весь архив
  каждые несколько секунд.
- Запись можно удалить кнопкой «Удалить везде». Удаление распространяется на все узлы,
  включая временно выключенные компьютеры; tombstone-запись защищает от воскрешения старой копии.
- Старая history.json импортируется при первом запуске SQLite и не удаляется.
- В config.ini есть local_name — подсказка для собственного локального DNS-имени.
- Дополнительные Python-пакеты не нужны.

БЫСТРЫЙ СТАРТ
-------------
1. Нужен Python 3.8 или новее. При установке включи Add python.exe to PATH.
2. Закрой старую версию ClipHouse на ВСЕХ компьютерах.
3. Замени файлы проекта новой версией на каждом компьютере. Не запускай одновременно
   старую и новую версии: протокол версии 3 синхронизирует также удаления. Для надёжного
   удаления везде обнови ВСЕ компьютеры до этой версии.
4. Открой config.ini, настрой при необходимости history_dir, auto_capture и local_name.
5. Запусти Start_ClipHouse.bat на каждом компьютере.
6. Разреши доступ в Windows Firewall для частной сети, если Windows спросит.
7. Открой LAN-адрес из консоли на другом ПК или телефоне, подключённом к тому же Wi-Fi.

АДРЕСА: ПОЧЕМУ ИХ ДВА
---------------------
127.0.0.1 — адрес самого устройства. На каждом устройстве он означает это устройство,
поэтому на телефоне 127.0.0.1 НЕ ведёт на твой компьютер.
192.168.x.x — IP компьютера в домашней сети. Именно его можно открыть на телефоне
или на другом ПК.

Чтобы использовать короткую закладку, в config.ini есть:
  [web]
  local_name = clip.home

Можно изменить на clipboard или clip.home.arpa. Это имя только для подсказки в консоли; само изменение INI не создаёт DNS-запись.
Нужно один раз сопоставить имя с IP компьютера в локальном DNS роутера. В Keenetic
CLI команда ip host добавляет статическое соответствие имени и IP. Например, если
ClipHouse-компьютер сейчас имеет 192.168.1.59:
  ip host clip.home 192.168.1.59
  system configuration save

Перед этим желательно закрепить IP 192.168.1.59 за этим компьютером в DHCP настройках
роутера. Иначе IP может измениться, и закладка перестанет открываться. После создания
DNS-записи используй одну закладку на всех устройствах:
  http://clip.home:8787/

Можно использовать clip.home, clipboard или clip.home.arpa. DNS-запись на роутере
должна совпадать с local_name. Keenetic поддерживает добавление локального соответствия
командой ip host. Учти: стандарт RFC 8375 рекомендует home.arpa вместо .home из-за риска
конфликтов; если хочешь короткий clip.home, он может работать при явной локальной записи,
но для наиболее стандартного варианта используй clip.home.arpa. Изменение INI само по себе
не создаёт DNS-запись.

ВАЖНО: ЕСЛИ ОТКРЫТЬ НЕСКОЛЬКО АДРЕСОВ
-------------------------------------
Если на одном компьютере открыть http://127.0.0.1:8787/ и
http://192.168.1.59:8787/, это два адреса одной и той же запущенной программы и одной
базы данных. Данные не дублируются. Может быть открыто несколько вкладок одновременно.
Если открыть адрес другого компьютера, это уже другой экземпляр и своя локальная SQLite
база; они обмениваются записями при включённой синхронизации.

SQLite И ХРАНЕНИЕ
-----------------
Основной файл базы:
  <history_dir>\history.sqlite3

Настрой каталог в config.ini, например:
  [storage]
  history_dir = D:\ClipHouseHistory

Или оставь:
  history_dir = %LOCALAPPDATA%\ClipHouse

Папка должна существовать или быть доступной для создания и записи. Не рекомендуется
использовать C:\Windows\Temp: временные файлы могут быть удалены очисткой Windows.

Если старая версия уже создала history.json, новая версия импортирует его при первом
запуске SQLite и оставит JSON на месте как резервную копию. Если перед первым запуском
ты изменишь history_dir, программа также попытается найти прежнюю history.json в
%LOCALAPPDATA%\ClipHouse.

Если SQLite уже работает и ты хочешь перенести её на другой диск:
1. Полностью останови ClipHouse.
2. Скопируй history.sqlite3 из старого каталога в новый. Не копируй работающую базу.
3. Измени history_dir в config.ini.
4. Запусти ClipHouse и проверь путь к SQLite в консоли.

База хранит всю историю, пока ты её сам не удалишь. В браузер при этом не загружается
весь архив: последние 50 записей — первая страница, кнопка «Старее» загружает следующую.
Поиск выполняется на сервере. На компьютерах с огромным архивом FTS5 обычно значительно
быстрее обычного поиска по тексту. Автоматическое удаление старых записей по умолчанию
не включено: это сохраняет архив и не создаёт неожиданных потерь.

УДАЛЕНИЕ НА ВСЕХ УСТРОЙСТВАХ
---------------------------
В каждой карточке истории есть кнопка «Удалить везде». После подтверждения запись сразу
удаляется из локальной БД и создаётся компактная tombstone-запись (метка удаления).
Эта метка синхронизируется с другими узлами, в том числе когда выключенный компьютер
позже вернётся в сеть. Если старый экземпляр записи придёт от другого компьютера,
ClipHouse 3.0 проверит tombstone и не добавит удалённую запись обратно.

Метки удаления оставляются в SQLite намеренно: если их сразу удалять, долго выключенный
компьютер мог бы прислать старую запись обратно. Они хранят ID и время удаления, а не
текст записи, поэтому значительно компактнее исходного содержимого. SQLite повторно
использует освобождённые страницы; размер файла базы на диске может не уменьшиться сразу.

НАСТРОЙКИ config.ini
--------------------
[server]
http_port = 8787
discovery_port = 8788

[storage]
history_dir = %LOCALAPPDATA%\ClipHouse

[clipboard]
auto_capture = true
max_text_chars = 100000

[web]
local_name = clip.home

http_port — порт сайта. Если меняешь его, новая закладка должна содержать новый порт.
discovery_port — UDP-порт автообнаружения узлов. Он должен совпадать на всех ПК.
history_dir — папка SQLite; на разных ПК может быть разная буква диска.
auto_capture=true — автоматический захват текстового системного буфера Windows.
auto_capture=false — добавление текста только через сайт.
max_text_chars — максимальная длина одной записи.
local_name — короткое имя, для которого можно отдельно создать DNS-запись на роутере.

СИНХРОНИЗАЦИЯ МЕЖДУ КОМПЬЮТЕРАМИ
--------------------------------
На всех компьютерах должна быть версия ClipHouse 3.0 и совпадать HTTP- и UDP-порты.
Узлы обнаруживают друг друга широковещательным UDP и передают новые/не полученные записи
фоновыми партиями. Первый обмен с компьютером, на котором уже большой архив, может идти
постепенно, зато полный архив не передаётся каждые несколько секунд.

АВТОЗАХВАТ И БЕЗОПАСНОСТЬ
-------------------------
В Windows ClipHouse опрашивает системный текстовый буфер примерно каждые 0,35 секунды.
При auto_capture=true в историю могут попасть любые скопированные тексты, в том числе
ключи, пароли и другие секреты. Все запущенные узлы синхронизируют эти записи.
На iPhone/Android веб-страница не может постоянно читать системный буфер в фоне, но
можно вручную вставлять/добавлять текст и копировать записи кнопками сайта.

Не делай проброс портов 8787/8788 из интернета на роутере. Доступ предназначен для
доверенной домашней сети. Для разрешения в Windows Firewall используй Allow_Firewall.bat
от имени администратора; правила должны оставаться только для профиля Private.

CTRL+C И АВТОЗАПУСК
-------------------
Ctrl+C в окне консоли ClipHouse останавливает сервер. Ctrl+C в других приложениях
работает как обычное копирование. Enable_Autostart.bat добавляет скрытый запуск при входе
в Windows; Disable_Autostart.bat убирает его. После настройки автозапуска не перемещай
папку с программой.
