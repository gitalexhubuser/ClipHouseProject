ClipHouse — общий буфер обмена и история для домашней сети
===========================================================

ЧТО ЭТО
-------
Небольшой Python-сервер без дополнительных библиотек. На Windows он
автоматически замечает текст, скопированный в обычных программах, показывает
его в локальной веб-странице и синхронизирует историю с другими запущенными
экземплярами ClipHouse в той же подсети. Телефон открывает эту же страницу
через браузер и может добавить или скопировать текст.

БЫСТРЫЙ СТАРТ
-------------
1. Убедись, что установлен Python 3.8 или новее. Для Windows: python.org.
   При установке отметь Add python.exe to PATH.
2. Распакуй папку ClipHouseProject на каждый компьютер, где нужен общий буфер.
   Можно положить в разные места и на разные диски — программа от этого не зависит.
3. На каждом компьютере запусти Start_ClipHouse.bat.
4. Если Windows Firewall спросит о доступе Python к сети, разреши доступ только
   для частных сетей (Private networks), не для Public networks.
5. В окне появится адрес вида http://192.168.1.50:8787/ . Открой его в браузере.
6. На телефоне подключись к домашнему Wi-Fi и открой LAN-адрес компьютера,
   на котором запущен ClipHouse.

КАК ИСПОЛЬЗОВАТЬ
----------------
- На компьютере выделяешь текст и нажимаешь Ctrl+C — примерно через секунду он
  появится в ClipHouse и будет разослан другим работающим узлам.
- На странице можно нажать «Копировать» возле записи. На компьютере текст
  попадёт в системный буфер; на телефоне браузер попробует скопировать текст.
- Чтобы вручную отправить текст с телефона, вставь/напиши его в верхнем поле и
  нажми «Добавить в общий буфер».
- История свёрнута: нажми «История буфера», чтобы раскрыть список.
- История хранится на каждом узле отдельно в общей логической копии:
  %LOCALAPPDATA%\ClipHouse\history.json
- История ограничена последними 60 записями; один текст — до 100 000 символов.

ЗАПУСК НА НЕСКОЛЬКИХ КОМПЬЮТЕРАХ
-------------------------------
ClipHouse использует UDP broadcast для автоматического обнаружения других
экземпляров в локальной сети. Затем серверы обмениваются новыми записями.
Запусти Start_ClipHouse.bat на каждом нужном ПК. Новые записи реплицируются
между узлами автоматически. Желательно, чтобы часы Windows были настроены
правильно. Синхронизация между отдельными гостевыми Wi-Fi/VLAN может быть
заблокирована настройками роутера.

Если Windows Firewall блокирует доступ:
- сначала проверь уведомление Windows Defender Firewall;
- если уведомления нет, щёлкни Allow_Firewall.bat правой кнопкой и выбери
  «Запуск от имени администратора» на каждом ПК. Правила ограничены профилем
  Private и портами TCP 8787 + UDP 8788.

АДРЕС, КОТОРЫЙ ЛЕГКО ЗАПОМНИТЬ
-----------------------------
У каждого узла есть адрес по IP, который выводится в консоль.
Чтобы использовать короткий адрес вроде http://clip.home.arpa:8787/:
1. Зарезервируй постоянный LAN-IP для одного всегда включённого ПК в настройках
   DHCP роутера. Например, 192.168.1.50. Адрес зависит от твоей сети.
2. На Keenetic открой CLI/командную строку роутера и добавь локальную DNS-запись:
       ip host clip.home.arpa 192.168.1.50
       system configuration save
   Замени IP на фактический зарезервированный адрес ПК. Запись должна указывать
   на компьютер, а не на IP самого роутера.
3. Устройство должно использовать Keenetic как DNS-сервер. Если имя не открывается,
   переподключи Wi-Fi или обнови DHCP lease. В любом случае можно использовать
   IP-адрес напрямую и сохранить его как закладку.

DNS-имя указывает на один конкретный компьютер. Остальные узлы продолжают
обмениваться данными между собой, но для доступности закладки этот компьютер
должен быть включён. Для доступа по другому узлу используй его собственный IP.

АВТОЗАПУСК WINDOWS
------------------
После проверки запусти Enable_Autostart.bat. Он создаёт скрытый VBS-запуск при
входе пользователя в Windows. Папку с ClipHouse.py после этого не перемещай.
Для отключения запусти Disable_Autostart.bat. Скрытый запуск пишет ошибки в
%LOCALAPPDATA%\ClipHouse\startup.log.

ВАЖНЫЕ ОГРАНИЧЕНИЯ И БЕЗОПАСНОСТЬ
--------------------------------
- Это для доверенной домашней сети, не для открытого публичного Wi-Fi.
- Не настраивай проброс TCP 8787 или UDP 8788 из интернета на роутере.
- Это история текстовых данных. Не копируй туда пароли/секреты, если не хочешь,
  чтобы они сохранялись на всех запущенных узлах.
- Автоматический захват системного буфера реализован для Windows. Если скопирован
  очень длинный текст (более 100 000 символов), он не попадёт в историю.
- Когда один компьютер выключен, он не получает изменения до следующего запуска.
- Проверена базовая работа HTTP/API и синтаксис Python в тестовом окружении, но
  сетевой обмен и запись системного буфера нужно проверить на реальных Windows-ПК.
